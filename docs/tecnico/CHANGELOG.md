Toda mudança que entra na `develop` ganha uma linha aqui, no mesmo PR (ver [como-manter.md](como-manter.md)). Do mais recente ao mais antigo. O que aconteceu antes de 8/nov/2026 está resumido em [historico.md](historico.md).

- #262 IPTU pela notificação de lançamento de São Paulo (pedido do Moises, 9/nov/2026). **Serviço novo** `services/iptu` (Node 22 + Playwright/Chromium + pdf.js; Cloud Run `terrenos-iptu`, imagem `mcr.microsoft.com/playwright`): `POST /consultar {inscricao_id}` confere o login do Supabase (`/auth/v1/user`), lê a inscrição com o token de quem pediu (RLS; só SQL de 11 dígitos de São Paulo), exige editor (`app.empresas_edicao`), limita 40 consultas por pessoa por hora, emite a 2ª via no portal `notcertiptu.prefeitura.sp.gov.br` com a Senha Web (`IPTU_CPF`/`IPTU_SENHA`, Secret Manager), uma por vez (fila de 8, 2 min), lê o PDF por rótulos e posições (`src/notificacao.js`; rótulo que falta = erro, nunca zero) e insere em `app.inscricao_valores` com o token da pessoa (não cria revisão se o exercício e os valores forem iguais). `POST /notificacao` devolve o PDF sem gravar. Login recusado bloqueia novas tentativas por 30 min; captcha para com 409. Código próprio: o repositório de referência (charbonnev/segunda-via-iptu) não tem licença e não foi copiado. **Banco** (editado no lugar): `inscricao_valores.notificacao jsonb` (objeto); 2 testes em `regras.sql`. **Caddy:** `/iptu/consultar|notificacao|saude` → `{$IPTU_URL}` (sem a variável, 502). **Front:** `ficha/Iptu.tsx` (seção IPTU depois de Áreas e dimensões na aba Terreno; o detalhe é lido à parte, para não quebrar a ficha sem a coluna). Testes do serviço: `cd services/iptu && npm test` (leitura do PDF com uma notificação fictícia). **Não testado contra o portal de verdade** (sem a senha na sessão); não se sabe se a Senha Web emite para SQL de outro dono. Ver `integracoes.md` §10b, `deploy-e-ambientes.md` e `seguranca.md`.
